Documentation map

  • Architecture: the goals, constraints, and proposed platform direction.
  • ADRs: technical decisions and their current status. Proposed does not mean accepted.
  • Security: threat model, reporting policy, and trust boundaries.
  • Packages: source provenance, license review, checksums, tests, and update responsibility.
  • Package architecture: a proposal for immutable package payloads, recoverable transactions, official repository trust, and optional compatibility imports.
  • Installer: safe installation planning and validation before any disk-writing implementation.
  • Build system: build stages, isolation, inputs, logs, and artifact verification.

Not documented as finished

Installation, upgrades, recovery, package management commands, hardware support, and release procedures will be documented after they are implemented and tested. Until then, this site links to research and planning material rather than presenting imagined commands as working features.

Documentation changes are welcome. Please distinguish verified behavior from proposals, assumptions, and planned work.
