05 / Community

Build the project with us.

Useful contributions include careful research, documentation, test design, packaging experiments, accessibility fixes, and reproducible bug reports. The project is early-stage, so proposals and evidence matter.

Ways to contribute

  • Review architecture proposals and explain trade-offs with sources.
  • Improve documentation for accuracy, accessibility, and clarity.
  • Help define package review, provenance, license, and vulnerability workflows.
  • Develop small, isolated experiments with clear inputs and reproducible results.
  • Review the website for keyboard access, mobile layouts, broken links, and misleading wording.

Before opening a pull request

  1. Search existing issues and pull requests to avoid duplicated work.
  2. For a significant technical direction, open an issue or ADR proposal before implementing a large change.
  3. Keep changes focused and explain the problem they solve.
  4. Document upstream sources, license obligations, tests performed, and limitations.
  5. Never commit credentials, private keys, access tokens, or unreviewed binary artifacts.

Code and review expectations

Changes should be small enough to review, use clear commit messages, and include appropriate checks. Security-sensitive changes, release infrastructure, package signing, and publishing should receive additional scrutiny. A successful CI run is useful evidence, not a guarantee of correctness.
