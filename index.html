01 / Engineering principles

Designed carefully.
Proven in practice.

Good operating systems are more than a desktop and a package list. They need dependable infrastructure, clear decisions, and tests that demonstrate what works.

01
⌘

Own the architecture

Deku's system design, tools, and user experience will be shaped around explicit requirements and measurable trade-offs.

02
⛨

Security by construction

Traceable sources, isolated builds, narrow privileges, and signed release metadata belong in the design from the start.

03
↻

Reliability is tested

Installation, updates, recovery, and compatibility must pass repeatable tests before they become promises to users.

02 / Platform foundations

Every layer has
a clear purpose.

We are developing the foundations in stages: package metadata and transaction design, reproducible build workflows, a safe installer, and a transparent release process. Each layer advances when its tests and dependencies are ready.

03 / Roadmap

Progress you
can follow.

Milestones are sequenced around technical dependencies and evidence. There is no promised release date until the system can be built, installed, and tested reliably.

Open the detailed roadmap ↗

  1. CURRENT PHASE

    Architecture and tooling

    Repository structure, technical decisions, package metadata experiments, and automated validation.

  2. NEXT MILESTONE

    Build a repeatable base

    Prototype a minimal base system with pinned inputs, build logs, and verifiable artifacts.

  3. AFTER BASE IMAGE

    Install and boot testing

    Exercise the installer and base image in disposable virtual machines, including failure and recovery paths.

  4. RELEASE GATE

    Public preview

    Publish only when checksums, signatures, documentation, known issues, and test evidence are available.
