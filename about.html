Foundation / About

An open-source foundation for distinct, useful projects.

Deku Foundation is the public home for an independent, multi-project engineering effort. Deku Linux is the first platform project; language research and shared developer practices are separate workstreams with their own scope and maturity.

Mission

Build useful, maintainable and accessible open-source software through transparent engineering, careful upstream reuse and testable decisions. The portfolio may span operating systems, developer tools and Arabic-first programming technology without forcing every project into one technical stack.

Scope note: “Deku Foundation” is the public name of this engineering organization. This page does not claim registered nonprofit status, certification, or production readiness for any project.

Current portfolio

  • Deku Linux — prototype: package metadata and dependency planning, build-plan validation, system-manifest validation and non-destructive installation planning. There is no public ISO, production package repository or supported release.
  • Arabic-first programming language — proposal: the design direction is a Rust-hosted prototype first, with explicit Unicode, bidirectional-text, diagnostics and interoperability rules. No compiler or separate language repository is claimed to exist.
  • Shared engineering — practices: CI, supply-chain review, upstream evaluation, documentation, localization and release gates are cross-project work, not standalone products until maintained implementations exist.

How projects progress

  1. Research: define a user need, review mature alternatives and record license, maintenance and security trade-offs.
  2. Specification: write an RFC or architecture decision with alternatives, measurable exit criteria and known limitations.
  3. Prototype: keep changes on dev, test the smallest useful vertical slice and publish evidence from CI.
  4. Promotion: update main only after relevant tests, documentation and risk review pass. A green workflow validates its configured checks; it is not a general security or production certificate.

Principles

  • Upstream first: configure, integrate, package or contribute to a maintained upstream project before creating a long-lived fork.
  • Open by default: source, design decisions, issues and limitations should be reviewable.
  • Small, clear ownership: no repository without a charter, a responsible maintainer, a first milestone and a testable slice.
  • Evidence-led communication: distinguish proposals, prototypes, stable releases and archived work. Do not publish invented metrics, dates or feature claims.

Ways to participate

Review a current repository, report a reproducible issue, improve documentation or translations, or discuss the language and architecture proposals. Start from the repository directory and its contribution links. Keep security-sensitive disclosures private and follow the policy in the affected repository.
